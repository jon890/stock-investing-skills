# ADR: 병목 찾기와 텐베거 발굴 스킬을 분리한다

## 상태

채택.

## 배경

기존 `daily-market-decision` 스킬은 섹터 히트맵 분석, 병목 판정, 텐베거 후보 선별, 밸류에이션 리포트를 한 번에 담는다.
사용자가 정한 실제 목표는 두 개다.

| 목표 | 내용 |
| --- | --- |
| 섹터 병목 찾기 | 섹터 히트맵과 시장 데이터를 보고 가치사슬 병목을 찾는다 |
| 병목 안의 텐베거 찾기 | 병목이 일어난 산업에서 3년 안에 10배 여지가 남은 종목을 찾는다 |

하나의 스킬에 두 목표를 모두 넣으면 호출 조건과 검증 기준이 흐려진다.
또한 매일 의사결정이라는 이름은 실제 목표보다 넓다.

## 결정

`daily-market-decision` 은 장기적으로 제거하고, 스킬을 다음처럼 나눈다.

| 스킬 | 책임 |
| --- | --- |
| `sector-bottleneck` | 시장과 섹터 데이터를 받아 병목 산업 그룹을 찾는다 |
| `tenbagger-pick` | 확정된 병목 안에서 텐베거 후보를 찾고 가치평가로 검증한다 |
| `wsaj-investing-brain` | 월가아재 자료 기반 원칙과 용어를 근거와 함께 검색해 답한다 |

Claude Code 와 Codex 는 모두 `skills/` 를 실제 원본으로 읽는다.
`.claude/skills` 와 `.agents/skills` 는 `skills/` 를 가리키는 호환 경로로 둔다.

## 대안

| 대안 | 판단 |
| --- | --- |
| `daily-market-decision` 을 계속 확장 | 기각. 이름과 책임이 넓어지고, 사용자가 요청한 두 스킬 구조와 맞지 않는다 |
| 스킬을 도구별 경로에 복사 | 기각. Claude Code 와 Codex 사이에 내용이 갈라질 수 있다 |
| 원본 `skills/` 와 도구별 심볼릭 링크 | 채택. 단일 원본을 유지하면서 두 도구의 탐색 경로를 만족한다 |

## 결과

병목 분석과 종목 발굴은 독립적으로 실행하고 검증할 수 있다.
사용자는 “어느 섹터가 병목인가”와 “그 병목에서 어떤 종목을 볼 것인가”를 따로 물을 수 있다.

`daily-market-decision` 을 즉시 삭제하지는 않는다.
후속 스킬이 같은 결과를 내고 검증을 통과한 뒤 제거한다.

## 검증 조건

1. `sector-bottleneck` 은 종목 목표가 없이 병목 그룹을 낸다.
2. `tenbagger-pick` 은 병목 그룹 입력 없이는 종목 결론을 내지 않는다.
3. `wsaj-investing-brain` 은 투자 원칙 답변에 증거 ID 를 붙인다.
4. 세 스킬은 `skills/` 에만 원본을 둔다.
5. `CLAUDE.md`, `.claude/skills`, `.agents/skills` 의 심볼릭 링크가 끊어지지 않는다.
