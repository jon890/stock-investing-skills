# 주식투자 하네스 흐름

## 전체 흐름

기본 흐름은 `섹터 히트맵 → 병목 판정 → 텐베거 후보 → 가치평가 → 안전마진 판단` 이다.
질문이 티커에서 시작하면 종목을 먼저 받되, 병목 확인을 건너뛰지 않는다.

| 단계 | 입력 | 처리 | 출력 |
| --- | --- | --- | --- |
| 섹터 히트맵 수집 | valley 로그인 세션, 시장 구분 | 기간별 등락과 밸류에이션 배수를 모은다 | `reports/universe-<MARKET>-<YYYYMMDD>.json` |
| 병목 판정 | 유니버스 JSON | 다섯 팩터를 표준화하고 가중합한다 | 상위 병목 그룹, 결측 진단, `bottleneck_context` |
| 후보 선별 | 검증된 `bottleneck_context` | 시총, 성장률, 마진 확대, 기대 분산으로 줄인다 | 텐베거 후보 목록 또는 참고 가치평가 |
| 일반 가치평가 | 후보 티커와 입력 가정 | DCF, 역DCF, 상대가치, 손익비를 계산한다 | 목표주가와 보류 사유 |
| 특수 상황 가치평가 | 일반 가치평가로 설명하기 어려운 사건 | IPO, M&A, 은행, 실적발표 직후, 브랜드 소비재를 별도 기준으로 본다 | 별도 판단 또는 보류 |
| 안전마진 판단 | 가치평가 결과와 근거 품질 | 상승 여력, 하방, 손익비, 근거 신뢰도를 함께 본다 | 매수 후보, 보류, 재평가 |

## 정상 흐름

사용자가 "오늘 어느 섹터가 병목인가"처럼 시장에서 시작하면 `sector-bottleneck` 이 먼저 돈다.
이 스킬은 시장 유니버스를 수집하고 병목 그룹만 판정한다.
개별 종목 매수 판단은 하지 않는다.

상위 병목 그룹이 나오면 `tenbagger-pick` 으로 넘긴다.
넘길 때는 그룹 코드, 유니버스 JSON 경로, 병목의 실체, 지속 기간, 통제 주체, 출처를
`bottleneck_context` 로 함께 넘긴다.
병목 근거가 검증되지 않으면 종목은 `reference_only` 로 남긴다.
`tenbagger-pick` 은 병목 그룹 안에서 후보를 고르고 가치평가로 연결한다.

병목 그룹에서 시작하면 먼저 후보 목록만 만든다.
티커에서 시작하면 같은 문맥으로 그룹을 역확인한 뒤 가치평가를 붙인다.
어느 흐름에서도 `bottleneck_context` 없이 종목을 최종 후보로 올리지 않는다.

가치평가 결과는 세 갈래로 끝난다.

- 매수 후보: 안전마진과 손익비가 있고, 3년 10배 조건의 핵심 가정이 검증된다.
- 보류: 상승 여력은 있어도 근거 품질, 손익비, 병목 지속성이 부족하다.
- 재평가: 실적발표, 가이던스 변경, 병목 해소 신호처럼 새 정보가 나오면 다시 본다.

## 티커 직행 흐름

사용자가 특정 티커를 바로 주면 `tenbagger-pick` 이 시작점이 된다.
이 경우에도 종목이 속한 산업 그룹을 확인한다.

| 확인 | 통과 | 실패 |
| --- | --- | --- |
| 산업 그룹이 병목 상위권인가 | 후보 선별과 가치평가를 계속한다 | 병목 밖 종목으로 표시하고 참고 가치평가만 한다 |
| 3년 10배가 가능한 시총인가 | 텐베거 후보로 남긴다 | 일반 투자 후보로만 다룬다 |
| 성장률과 마진 확대가 있는가 | 병목 수혜 후보로 본다 | 단순 저평가나 회복주로 분리한다 |
| 현재 데이터 출처가 완전한가 | 가치평가를 후보 판정에 쓴다 | 계산 결과를 참고용으로만 남긴다 |
| 특수 상황 검토가 끝났는가 | 일반 가치평가를 계속한다 | 보류하거나 별도 모형으로 넘긴다 |

티커 직행은 사용자의 관심 종목을 빠르게 검토하는 길이다.
하네스의 기본 철학을 바꾸는 길은 아니다.
병목이 설명되지 않으면 텐베거 후보로 올리지 않는다.

## 데이터 실패 흐름

valley 데이터는 로그인 세션과 화면 API에 의존한다.
조회 결과가 비거나 결측이 많으면 점수를 억지로 내지 않는다.

| 실패 상황 | 판정 | 다음 행동 |
| --- | --- | --- |
| 히트맵 응답이 비어 있음 | 로그인 만료 가능성이 크다 | 현재 브라우저 URL을 확인하고 수집을 중단한다 |
| `contentType` 이 잘못됨 | 빈 배열이 올 수 있다 | `USA` 또는 `KOR` 만 다시 호출한다 |
| 기간 수익률 커버리지가 98% 미만 | 병목 점수를 믿지 않는다 | 결측 기간과 개수를 리포트에 남기고 중단한다 |
| 배수 결측이 많음 | 수요 수준과 가격결정력 해석이 약해진다 | 결측률을 표시하고 후보 선별 강도를 높인다 |
| 종목 접미사가 틀림 | 200 응답이어도 값이 비어 있다 | 거래소별 접미사를 다시 확인한다 |
| 한국 시장 컨센서스가 부족함 | 병목 점수 신뢰도가 낮다 | 한국은 병목 관찰까지만 하고 텐베거 선별은 보류한다 |

데이터 실패는 보류 결론으로 남긴다.
빈 값에 0을 넣어 순위를 만들지 않는다.

## 일반 가치평가 흐름

일반 가치평가는 사업이 계속기업으로 유지된다고 볼 수 있을 때 쓴다.
입력 가정은 `scripts/inputs/<TICKER>.json` 이 소유하고, 계산 코드는 종목을 몰라야 한다.

| 절차 | 판단 |
| --- | --- |
| DCF | 현금흐름의 오늘 값을 계산한다 |
| 역DCF | 현재 주가가 요구하는 성장률, 마진, 할인율을 역산한다 |
| 상대가치 | 동종군이 매기는 배수 범위를 본다 |
| 손익비 | 같은 방법 안에서 상방과 하방을 비교한다 |
| 3년 텐베거 | 보유 기간 끝 시점의 기업가치를 시나리오별로 직접 구한다 |

대상 성장률이 동종군 범위를 벗어난 배수는 상대가치에서 제외한다.
쓸 수 있는 배수가 하나도 없으면 상대가치를 보류하고 후보 승격을 막는다.

절대가치와 상대가치는 가중평균하지 않는다.
둘이 다르면 어느 쪽 가정이 시장과 다른지 적는다.

## 특수 상황 가치평가 흐름

일반 가치평가가 설명력을 잃는 상황은 별도로 분기한다.
분기 기준을 충족하지 못하면 억지로 일반 모형에 넣지 않는다.

| 상황 | 별도 확인 | 결론 |
| --- | --- | --- |
| IPO 직후 | 락업 해제, 유통 물량, 공모가 산정 근거 | 데이터가 짧으면 보류한다 |
| M&A 또는 분할 | 거래 조건, 희석, 합병 후 재무제표 | 기존 동종군 비교를 그대로 쓰지 않는다 |
| 은행과 보험 | 자본비율, 대손, 금리 민감도, PBR | EV 배수 중심의 일반 흐름과 분리한다 |
| 실적발표 직후 | 회사 가이던스와 컨센서스 갱신 여부 | 데이터 제공자 값이 늦으면 가이던스로 교체한다 |
| 브랜드 소비재 | 마진, 성장률, 시장 침투율, 지역 확장, 프리미엄 지속성 | 유명세만으로 높은 배수를 정당화하지 않는다 |

특수 상황은 기대수익이 커 보여도 근거가 좁다.
근거가 좁으면 안전마진을 넓히거나 보류한다.

## 투자 Wiki 연구 보조 흐름

투자 거장 자료는 투자 판단의 자동 결론이 아니라 근거 검색 계층이다.
질문이 철학, 용어, 가치평가 방식에 관한 것이면 `investing-wiki` 가 선택한 expert 의 공개 자료 근거를 찾는다.
기존 월가아재 질문은 `wsaj-investing-brain` 이 `expert_id=wsaj` 로 위임해 처리한다.

일반적인 투자 용어 뜻은 `docs/glossary.md` 에서 먼저 찾는다.
특정 expert 가 그 용어를 어떻게 쓰는지 묻는 질문은 `wiki/experts/<expert_id>/glossary.md` 와 증거 저장소를 함께 읽는다.
공통 정의는 expert 의 주장처럼 인용하지 않고, expert 별 설명은 근거 ID 없이 일반 상식으로 넓히지 않는다.

답변은 다음 순서로 만든다.

| 순서 | 내용 |
| --- | --- |
| 결론 | 질문에 대한 짧은 답 |
| 근거 | 자료 종류, 제목, URL이나 문헌 위치, `source_locator`, 확인 요약 |
| 해석 | 하네스가 투자 프로세스에 연결한 설명 |
| 한계 | 근거 부족, 자료 사이 충돌, 현재 데이터 필요 여부 |

근거가 부족하면 답변을 중단한다.
인물의 말투를 흉내 내거나, 최신 종목에 대해 특정 expert 가 현재 판단한 것처럼 말하지 않는다.
여러 expert 를 함께 묻는 질문은 expert 별 근거를 나눠 제시하고, 공통 개념은 `wiki/concepts/` 의 연결 문서가 있을 때만 합성한다.

## 종료 상태

| 상태 | 뜻 | 다음 행동 |
| --- | --- | --- |
| 매수 후보 | 병목, 가치평가, 안전마진이 함께 통과했다 | 리포트를 저장하고 이후 재평가 조건을 적는다 |
| 보류 | 핵심 근거가 약하거나 손익비가 부족하다 | 부족한 근거와 재확인 조건을 적는다 |
| 재평가 | 새 데이터가 기존 결론을 바꿀 수 있다 | 실적발표, 가이던스, 병목 해소 신호를 기다린다 |
| 중단 | 데이터 실패나 권한 문제가 있다 | 실패 사유를 남기고 계산을 하지 않는다 |
