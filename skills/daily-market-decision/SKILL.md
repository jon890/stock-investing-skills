# 텐베거 발굴 워크플로

목표와 병목의 정의, 팩터 가중치의 근거는 `~/finance-skills/docs/prd.md` 가 소유한다.
데이터 경로와 실측 함정은 `~/finance-skills/CLAUDE.md` 가 소유한다.
이 문서는 실행 절차만 담는다.

세 단계를 순서대로 돈다.
사용자가 종목을 지목했으면 3단계부터 시작한다.
사용자가 섹터만 지목했으면 2단계부터 시작한다.

## 0. 준비

```bash
B=~/.claude/scripts/browser-driver
PAGE=$($B open "https://www.valley.town/markets/sector-heatmap" 30000)
$B url "$PAGE"
```

주소가 로그인 화면이면 멈추고 사용자에게 로그인을 요청한다. 추측으로 진행하지 않는다.

## 1. 병목을 찾는다

### 1.1 유니버스를 받는다

```bash
cd ~/finance-skills
scripts/fetch_universe.sh "$PAGE" USA reports/universe-USA-$(date +%Y%m%d).json
scripts/fetch_universe.sh "$PAGE" KOR reports/universe-KOR-$(date +%Y%m%d).json
```

시장당 약 490개 종목의 일곱 기간 등락과 밸류에이션 배수를 모은다.
2분 남짓 걸린다. 완료 줄에 찍히는 배수 결측 개수를 확인한다.

**같은 날 파일이 이미 있으면 다시 받지 않는다.** 장중에 여러 번 부르면 그때마다 값이 달라진다.

### 1.2 점수를 낸다

```bash
python3 scripts/bottleneck.py reports/universe-USA-$(date +%Y%m%d).json
```

산업 그룹별 병목 점수와 팩터별 표준점수가 나온다.
상위 세 그룹을 후보로 삼는다.

**점수만 보고 넘어가지 않는다.** 상위 그룹마다 다음을 확인한다.

- 수요와 가격결정력 표준점수가 둘 다 양수인가. 하나라도 음수면 병목이 아니라 자금 쏠림이다.
- 지속성이 양수인가. 음수면 한 기간만 튄 테마다.
- 기간별 초과수익에서 최근 1개월이 음수인데 1년이 크게 양수이면 병목이 풀리는 중일 수 있다.
  이때는 웹 검색으로 무엇이 공급 제약을 풀었는지 확인한다.

### 1.3 병목의 실체를 확인한다

점수는 어디를 볼지 알려줄 뿐 왜인지는 말하지 않는다.
상위 그룹의 대표 종목 이름으로 웹 검색해 다음 셋에 답한다.

- 무엇이 공급을 제약하는가. 생산능력인가, 기술 장벽인가, 계약 구조인가.
- 그 제약이 몇 년 유지되는가. 증설 발표가 있으면 그 시점이 병목의 끝이다.
- 누가 그 제약을 쥐고 있는가. 병목 안에서도 가격을 정하는 계층이 따로 있다.

세 질문에 답하지 못하면 그 그룹을 버리고 다음 순위로 내려간다.
점수만 높고 실체를 설명 못 하는 그룹은 텐베거가 나오지 않는다.

### 1.4 한국 시장은 별도로 다룬다

한국 종목의 컨센서스 추정 보유율이 26% 다.
수요와 가격결정력 팩터가 대부분 결측이라 병목 점수를 그대로 믿지 않는다.
자금 집중과 지속성만 참고하고, 종목 선별은 미국 시장에서 한다.
시가총액이 원화라 달러 기준 시총 상한도 그대로 쓰지 못한다.

## 2. 텐베거 후보를 고른다

```bash
python3 scripts/bottleneck.py reports/universe-USA-<날짜>.json --group 5710
```

시총 500억 달러 이하이면서 매출 성장 10% 이상인 종목만 남는다.

여기서 한 종목을 고른다. 우선순위는 이렇다.

1. 시총이 100억 달러 이하인 것. 10배 여지가 가장 크다.
2. 마진이 확대되는 것. 병목의 수혜를 실제로 받고 있다는 증거다.
3. 매출 성장률이 그룹 중앙값보다 높은 것.

**후보가 없으면 다음 순위 병목 그룹으로 내려간다.** 대형주로 억지로 채우지 않는다.
세 그룹을 다 봐도 후보가 없으면 그날은 1단계 리포트만 낸다.

## 3. 기업 풀리포트

### 3.1 비교군 데이터를 받는다

유니버스 파일에 이미 배수가 들어 있다. 같은 산업 그룹에서 8개 이상을 뽑는다.
시총 상하위를 섞는다. 대형주만 모으면 배수 중앙값이 낮게 잡힌다.

### 3.2 컨센서스를 두 단계로 검증한다

**첫째, 낡았는지 본다.** `EV ÷ LTM EV/Sales` 로 매출을 역산해 직전 회계연도 실적과 대조한다.
30% 넘게 어긋나면 그 종목의 배수를 전부 버린다.
소형 고성장주에서 1년 넘게 낡은 사례가 있다. CRDO 는 실제의 3분의 1 이었다.

**둘째, 가이던스와 맞는지 본다.** `EV ÷ 역년 EV/Sales` 를 회사가 최근 발표한 가이던스와 비교한다.
10% 넘게 어긋나면 가이던스로 교체하고, 교체 사실과 원래 값을 리포트에 남긴다.
실적 발표 다음 날에는 거의 항상 어긋난다.

**회계연도가 역년과 다르면 월수로 가중해 환산한다.**
4월이나 1월에 회계연도를 닫는 기업을 비교군의 역년 배수와 그대로 견주면 한 해가 어긋난다.

이 셋을 건너뛰면 결론이 뒤집힌다.

### 3.3 가정 파일을 쓴다

`scripts/inputs/<티커>.json` 을 만든다. 계산 코드는 고치지 않는다.

담을 것은 이렇다.

- `market`: 주가, 발행주식수, 순부채
- `fundamentals`: 직전 실적 매출, 현재 영업이익률, 가이던스, WACC 구성 요소
- `scenarios`: 기본과 낙관과 비관. 확률의 합이 1 이어야 한다
- `peers`: 비교군의 배수
- 각 값에 `_label` 또는 `_source` 를 붙여 출처를 남긴다

**추정의 출처를 세 가지로 구분해 표기한다.**

| 표기 | 뜻 |
| --- | --- |
| 가이던스 | 회사가 발표한 수치 |
| 컨센서스 | 애널리스트 추정 |
| 가정 | 내가 만든 값. 근거를 반드시 함께 적는다 |

시나리오 확률에는 근거를 붙인다.
가이던스 상향 이력, 고객 집중도, 경쟁 구도가 근거가 된다.

### 3.4 계산한다

```bash
python3 scripts/valuation.py <티커>
python3 scripts/valuation.py <티커> --json > reports/valuation-<티커>-<날짜>.json
```

한 번에 DCF 시나리오, 역DCF, 컨센서스 검증, 배수 적합성, 상대가치,
목표주가, 손익비, 텐베거 판정이 모두 나온다.

출력에서 반드시 읽어야 할 것은 이렇다.

- **잔존가치 비중이 80% 를 넘으면** 영구성장률을 더 낮춘다.
  5년 예측에서 70% 안팎은 정상이다.
- **DCF 가 현재가와 20% 넘게 갈리면** 역DCF 네 줄을 본다.
  현재 주가가 요구하는 할인율, 매출 CAGR, 영구성장률, 영업이익률 중
  어느 것도 현실 범위에 없으면 시장이 과열이다. 하나라도 가능하면 내 가정을 의심한다.
- **배수 적합성에서 `외삽` 이 뜬 배수는 쓰지 않는다.** 사유를 리포트에 적는다.
- **텐베거 판정은 배수 축소를 포함한 값이다.** 시나리오마다 최종 연도의 기업가치를 직접 구한다.
  매출이 몇 배가 되는지만 보면 안 된다. 그 규모에서는 배수가 성숙 기업 수준으로 내려온다.
  확률가중 배수가 목표주가 방향과 어긋나면 계산이 틀린 것이다.
- **판정이 `불가` 나 `미달` 이면** 그 종목은 목표에 맞지 않는다.
  리포트는 완성하되 결론에 그 사실을 먼저 쓰고, 다음 후보로 넘어갈지 사용자에게 묻는다.

### 3.5 판정을 세 갈래로 낸다

**절대가치와 상대가치를 합치지 않는다.** 가중평균한 목표주가는 어느 질문에도 답하지 못한다.

| 판정 | 무엇을 묻나 | 상방과 하방을 어디서 잡나 |
| --- | --- | --- |
| 절대가치 | 이 사업의 현금흐름이 주는 값 | 시나리오의 최선과 최악 |
| 상대가치 | 시장이 같은 부류에 매기는 값 | 동종 사분위의 위아래 |
| 텐베거 (2년) | 2년 안에 10배가 되는가 | 시나리오별 기말 주당가치 |

각 판정마다 적정가, 상방, 하방, 손익비, 진입가를 따로 낸다.
스크립트가 손익비 1:1, 2:1, 3:1 이 되는 가격을 함께 낸다.

| 손익비 | 의견 |
| --- | --- |
| 상승 여력 30% 초과이고 손익비 2 이상 | 매수 |
| 상승 여력 10% 초과이고 손익비 1 이상 | 비중 확대 |
| 상승 여력 -20% 미만 | 비중 축소 |
| 그 밖 | 보유 |

**두 방법이 갈리면 그 차이를 쓴다.** 어느 쪽이 높은지가 다른 뜻을 갖는다.

- 상대가치가 높으면 섹터 배수 자체가 현금흐름으로 정당화되지 않는 수준이다.
  섹터가 재평가되면 함께 내려온다.
- 절대가치가 높으면 이 기업의 현금흐름이 동종 평균보다 낫다는 뜻이다.
  시장이 아직 반영하지 않았다.

애널리스트 컨센서스 목표주가와 대조해 내 결론이 어디에 서 있는지 한 줄 남긴다.

## 4. 리포트

로컬 HTML 파일로 만든다. 외부에 게시하지 않는다.

```
~/finance-skills/reports/bottleneck-<YYYYMMDD>.html
~/finance-skills/reports/company-<티커>-<YYYYMMDD>.html
```

만든 뒤 경로를 사용자에게 알린다. 브라우저로 열어 보여주지 않는다.

담을 것은 이렇다.

- 판정을 맨 위에 둔다. 병목 그룹, 목표주가, 투자의견, 손익비, 텐베거 판정을 먼저 보인다.
- 모든 표에 단위와 기준일을 적는다.
- 가정에는 출처 표기를 붙인다.
- 계산 스크립트 경로와 원자료 JSON 경로를 남겨 숫자를 재현할 수 있게 한다.

## 내기 전에 점검할 것

- [ ] 같은 날 유니버스 파일을 중복으로 받지 않았다
- [ ] 병목 상위 그룹의 수요와 가격결정력이 둘 다 양수다
- [ ] 병목의 실체를 세 질문으로 확인했다
- [ ] 컨센서스와 회사 가이던스를 대조했다
- [ ] 모든 가정에 출처 표기가 붙었다
- [ ] 시나리오 확률에 근거가 붙었고 합이 1 이다
- [ ] 외삽이 뜬 배수를 쓰지 않았다
- [ ] 잔존가치 비중이 70% 아래다
- [ ] 손익비로 판정했다
- [ ] 텐베거 판정을 결론에 적었다
- [ ] 리포트의 모든 숫자가 스크립트 출력에서 나왔다
